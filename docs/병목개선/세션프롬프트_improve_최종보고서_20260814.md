## 1절. 이 문서의 형식은 성능 분석 세 편과 같습니다

최종 보고서는 GitHub에 공개하는 문서이므로 CLAUDE.md 1절(문단 중심, 기준 예시, 말투, 제목 규칙)을 전부 적용합니다. 원본데이터 폴더의 측정 보고서에 쓰는 표준 보고서 구조(개요·방법·결과)는 이 문서에는 쓰지 않습니다. 그 구조는 5편처럼 원본데이터 성격의 기록에만 씁니다.

값은 전부 출처 파일과 한 줄씩 대조하고, 계산값과 측정값을 구분하며, 확정하지 못한 것은 확정하지 못했다고 씁니다. 실제로는 나누지 못했던 후보를 처음부터 알았던 것처럼 쓰지 않습니다(1.8절 6번). 클럭 측정과 for문 대조처럼 두 갈래가 같은 결론에 닿은 자리는 두 갈래를 다 적습니다(1.8절 7번).

## 2절. 최종 보고서가 처음 다루는 것들

CLAUDE.md가 최종 보고서로 넘겨 둔 항목들입니다.

1. 클럭 측정의 값과 판정. 늘어난 시간 중 클럭이 설명하는 몫이 약 2%라는 판정과, 동시 실행 6과 12의 클럭이 같다는 값입니다.
2. JFR 측정(스트림 구현)의 판정. 9.5GB가 두 편차 메서드의 스트림 생성 세 문장에서 나온다는 것입니다.
3. 성능 분석 3편 4.5절의 분할 15점 표.
4. 보류한 누락 항목 넷. false sharing 후보 제외, 객체 하나가 캐시 덩어리를 넘어갈 때의 시간(82.9ns와 72.1ns), 워커 생성과 일감 훔치기 비용을 계산으로 제외한 것, 계측 관리 방침입니다.

여기에 이번에 끝난 작업이 더해집니다.

5. 증분 재계산 전환의 결과. 순차 57ms 안팎, 최고 배율 2.78배, 호출 1회당 할당 9,522MB에서 4.3MB로. 근거는 7번 폴더의 실행 여섯 개 종합입니다.
6. JFR 재측정 1회차. 남은 할당의 구성(팀 배정 복사본 약 70%, 배열 복사본 14.4%)과 스트림 클래스 소멸. 근거는 성능 분석 5편입니다.
7. 측정 종료 결정과 그 근거(카운터가 15점 전 구간을 덮고, 할당 구성은 설정과 무관하다는 것).
8. 미결로 남긴 것들. 워커 몰림의 원인 후보(풀 미종료), 평가 시간이 개수 비율보다 크게 줄어든 것, main 할당의 출처. 확정하지 못한 것으로 적습니다.

무엇을 넣고 무엇을 뺄지는 구성안 승인 때 사용자가 정합니다. 이 목록은 후보 전체이지 확정이 아닙니다.

## 4절. 앞 세션들에서 사용자가 지시한 작업 방식

1. 승인 없이 파일을 반영하지 않습니다. 구성안과 본문을 보이고 승인받은 뒤 반영합니다.
2. 두 작업을 한 번에 합치지 않습니다.
3. 한글이 든 문서는 통째로 옮겨 씁니다. 편집 도구로 한글을 끼워 넣으면 글자가 깨집니다. 고치기 전에 반드시 현재 상태를 먼저 읽습니다.
4. 결론을 정해 놓고 값을 맞추지 않습니다. 짐작을 값처럼 쓰지 않습니다.
5. 값마다 어느 회차의 어느 설정에서 나왔는지 밝히고, 찾지 못한 값은 쓰지 않습니다. 앞 세션에서 세션 프롬프트의 값 하나(3,420,000)가 원본 로그의 값(3,420,237)과 달라 원본까지 뒤져 바로잡은 일이 있습니다. 문서에 옮기는 값은 반드시 원본 파일에서 직접 확인합니다.
6. 설명은 구체적인 값으로 단계별로 보이고, 사용자가 이해하지 못한 부분은 압축하지 말고 풀어서 설명합니다.
7. 지적을 하나 받으면 같은 종류를 문서 전체에서 찾아 한 번에 고칩니다.
8. git 반영은 사용자가 직접 합니다. 필요하면 명령어만 정리해서 드립니다.
