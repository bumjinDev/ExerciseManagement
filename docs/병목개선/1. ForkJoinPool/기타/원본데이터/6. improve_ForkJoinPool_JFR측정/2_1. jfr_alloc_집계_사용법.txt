2. jfr_alloc_집계.py 사용법

무엇을 하는 도구인가

- JFR 기록 파일의 할당 표본(jdk.ObjectAllocationSample)을 집계해 엑셀로 저장한다.
- 두 편차 메서드의 9.5GB가 어느 줄에서 나오는지(문장별), 어떤 클래스로 이루어져 있는지(클래스별),
  각 클래스가 어떤 호출 사슬에서 만들어졌는지(스택 트레이스), 어느 스레드 몫인지(스레드별)를
  한 파일에 담는다. JMC Memory 화면에서 확인한 분석을 보고서 자료로 옮기는 용도다.
- 2026-08-05 세션에서 할당 지점을 판정할 때 쓴 집계의 재작성판이다. 원본 스크립트는
  그 세션의 작업 공간에만 있어 보존되지 않았고, 2026-08-06에 같은 방식으로 다시 만들어
  기준값 재현을 확인했다.

단위 원칙

- 시트의 값은 JMC 화면과 같은 이름, 같은 단위로 적는다. Alloc Total(GiB)과
  Total Allocation(%)은 JMC Memory 화면의 같은 이름 열과 같은 값이고, 스택과 줄별 분해는
  JMC Stack Trace 판의 Samples(표본 수), Percentage와 같은 기준이다.
- MB(100만 바이트)는 카운터 실측 문서(호출 1회당 9,522.1MB)와 대조하는 자리에만 함께 적는다.
- 모든 GiB와 % 값은 표본 무게의 합산이다. 총량의 확정 값은 프로브의 카운터
  실측(getThreadAllocatedBytes)을 쓴다.

필요한 것

- jfr 명령. JDK에 들어 있고, 이 기계의 기본 java(JDK 17)로 그대로 실행된다.
- 파이썬 3와 openpyxl. openpyxl은 5번 폴더의 엑셀 변환 도구들이 쓰는 것과 같다.

실행 순서 (명령창에서, 이 폴더로 이동한 뒤)

1) 기록 파일을 텍스트로 뽑는다. 스택을 전체 깊이로 뽑아야 엔진 프레임이 잘리지 않는다.
   jfr print의 기본 스택 깊이는 5라서 --stack-depth 64를 꼭 붙인다.

   jfr print --events jdk.ObjectAllocationSample --stack-depth 64 "1_1. improve_ForkJoinPool_JFR측정_병렬도6_말단작업분할개수_36_alloc.jfr" > alloc_print.txt

2) 뽑은 텍스트를 집계해 엑셀을 만든다. 출력 이름을 생략하면 기본 이름으로 저장한다.

   python "2. jfr_alloc_집계.py" alloc_print.txt

   기본 출력: 2_2. jfr_alloc_집계_병렬도6_분할36.xlsx
   다른 이름으로 저장하려면 두 번째 인자로 준다.

3) 콘솔 한글이 깨지면 chcp 65001 을 먼저 실행하고 다시 돌린다.

엑셀 시트 구성

- 클래스별 집계 : JMC의 Class 표와 같은 열(Samples, Alloc Total GiB, Total Allocation %)에,
                 그 클래스가 어느 줄에서 나왔는지의 줄별 표본 수(1230, 1278, 1280, 1281,
                 1284, 그 밖, 두 메서드 밖)를 붙였다.
- 스택 트레이스 : 클래스마다 호출 사슬 나무 전체. JMC Stack Trace 판을 표로 옮긴 것이다.
                 프레임은 객체가 만들어진 지점(안쪽)부터 바깥 호출자 순서이고, 아래 계층은
                 들여쓰기로 구분한다. 표본 비중은 그 클래스의 표본 수를 100으로 한 개수
                 기준이라 JMC의 Percentage와 같은 기준이다.
- 문장별 집계   : 세 문장(합 1230행, 평균 1278행, 분산 1280·1281·1284행)의 표본 수,
                 표본 비중(개수 기준), Alloc Total(GiB), 무게 비중. 판정 값(52.3 / 25.2 /
                 22.5)은 무게 비중이다.
- 스레드별 집계 : main과 워커의 몫(GiB와 MB). 아래에 순차 7회 몫(7 × 9,522.1MB)과
                 병렬 8회 몫의 계산을 붙여 대조한다. 몫의 비교는 표본 수가 아니라 무게로 한다.
- 판정 요약     : 판정 문장, 이 파일 재집계와 2026-08-05 집계 기준값의 대조,
                 카운터 실측과의 교차 확인, 주의 세 줄.

검증 기준값 (2026-08-05 세션에서 같은 기록 파일로 집계한 값)

  표본 수: 11,568개
  총량: 140,659MB (무게가 소수 첫째 자리로 반올림되어 있어 끝자리가 조금 다를 수 있다)
  문장별 무게 비중: 합 52.3% / 평균 25.2% / 분산 22.5%
  클래스 묶음: 도구 10.3% / 시작 19.4% / 변환 19.6% / 실행분(캡처 람다 포함) 50.7% / 그중 캡처 람다 1.9%
  카운터 실측과의 교차: 98.5% (총량 ÷ 호출 15회 × 9,522.1MB)

  2026-08-06 재작성판 검증 결과: 표본 수와 비중 전부 일치, 총량 140,674MB(차이 0.01%, 반올림 몫).

같이 있는 파일

- 1_1. ..._alloc.jfr : 기록 파일 원본. 병렬도 6, 분할 36, 2026-08-05 실행.
- 1. ..._ConsoleLog.txt : 같은 실행의 프로브 콘솔 로그. [할당] 줄에 카운터 실측이 있다.
- alloc_print.txt : 위 1) 명령이 만드는 중간 파일. 표본 11,568건이 낱개로 들어 있는
                    원본이고, 집계는 엑셀에 담긴다. 기록 파일에서 언제든 다시 만들 수 있다.
- 2_2. ...xlsx : 이 도구가 만드는 집계 엑셀.
