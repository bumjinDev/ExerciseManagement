[3.provelog_정리_종합.py 사용법]

_provelog.xlsx 파일들의 「정리」 시트만 꺼내 한 파일로 모은다.
2.probelog_to_xlsx.py 가 실행 하나마다 만들어 둔 _provelog.xlsx 가 입력이다.


■ 기본 — 이 스크립트가 있는 폴더의 _provelog.xlsx 전부

  py -3 "3.provelog_정리_종합.py"

  결과: improve_증분재계산_provelog_정리_종합.xlsx (같은 폴더)


■ 결과 파일 이름을 지정

  py -3 "3.provelog_정리_종합.py" -o "정리_종합_20260814.xlsx"


■ 다른 폴더를 훑기

  py -3 "3.provelog_정리_종합.py" -d "..\6. improve_for문" -o "결과.xlsx"


■ 특정 실행을 빼기 (파일 이름에 그 낱말이 들어가면 건너뛴다)

  py -3 "3.provelog_정리_종합.py" --except "말단작업분할개수" --except "19_36" --except "21_18"

  --except 를 하나도 안 주면 기본값 '말단작업분할개수' 하나가 적용된다.
  즉 13~23 발췌 실행은 기본으로 빠진다.


■ 파일을 직접 골라서 그 순서대로

  py -3 "3.provelog_정리_종합.py" "A_provelog.xlsx" "B_provelog.xlsx" -o "결과.xlsx"


──────────────────────────────────────────────────────────────
[만들어지는 시트]

  1. 종합
     A. 가져온 실행 목록 — 태그·시각·PID·워밍업·스윕 목록·순차 elapsed·파일 이름
     B 이후. 지표마다 표 하나. 행이 설정(순차 + 병렬 30개), 열이 실행이다.
       elapsed(ms) / speedup(배) / busyCore(개) / procCPU(ms) / workerCPU(ms) /
       평가 1회당 워커 CPU(ns) / 평가 반복문 합(ms) / 복사 합(ms) / GC(ms) /
       활동 워커 수 / 워커 장부 최대÷최소 / 평가 횟수 / 통과 횟수
       오른쪽 끝에 그 설정의 실행 사이 평균·최소·최대·최대÷최소가 붙는다.
     값은 「정리」 시트 그대로다. ns를 ms로 바꾼 자리만 1,000,000으로 나눴고
     그 자리는 열 이름에 (ms)라고 적어 두었다.

  2. 분석
     가. 검산 — 평가·통과 횟수가 실행 전체에서 하나인가, speedup 재계산과 맞는가
     나. 순차 기준선 — 실행별 순차 elapsed와 그 실행의 최고 배율 설정
     다. 실행 사이 재현성 — 설정별 elapsed 최대÷최소, 큰 것부터
     라. 설정 순위 — 실행마다 몇 등이었나, 등수 폭
     마. 코어 사용률 — busyCore ÷ 병렬도
     바. 워커 장부 균등도 — 최대÷최소와 '무한'이 나온 실행 수

  3번째 시트부터
     가져온 「정리」 시트를 실행 순서대로 하나씩, 값 그대로 옮긴다.
     시트 이름은 "3. 정리_0813_2121" 처럼 날짜와 시각이다.


──────────────────────────────────────────────────────────────
[읽는 순서와 거르는 규칙]

  · 파일 이름의 날짜·시각(..._20260813_21_21_provelog.xlsx)으로 정렬한다.
  · 이름이 ~$ 로 시작하는 엑셀 임시 파일은 건너뛴다.
  · 「정리」 시트가 없는 파일은 건너뛰고 화면에 사유를 찍는다.
  · 원본 파일은 열어서 읽기만 한다. 고치지 않는다.

필요한 패키지: openpyxl (없으면 pip install openpyxl)
