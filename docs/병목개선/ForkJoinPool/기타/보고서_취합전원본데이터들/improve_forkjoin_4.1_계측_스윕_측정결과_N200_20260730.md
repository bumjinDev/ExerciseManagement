## 1. 열 설명 (프로브 출력 그대로)

### 1.1 본 표의 열

| 열 | 뜻 |
|---|---|
| N(명) | 전체 인원 수 |
| 팀당 인원(명) | 팀 하나에 배정한 인원 수(정원). 이번 측정은 10으로 고정 |
| 구현 | 순차(improveSequential) 또는 병렬(improve) |
| 스레드(개) | 풀 병렬도. 순차 행은 `-` |
| 작업 분할 개수(개) | 이 설정에서 실제로 만들어지는 말단 작업 수. 목표 분할 개수와 같아야 한다. 순차 행은 `-` |
| elapsed(ns) | 메소드 전체 수행 시간(평균) |
| speedup(배) | 순차 elapsed ÷ 병렬 elapsed. 순차 행은 `-` |
| procCPU(ns) | 프로세스 전체 CPU 시간(평균). 코어들이 일한 시간의 총합 |
| busyCore(개) | 평균 바쁜 코어 수 = procCPU ÷ elapsed. 상한은 논리 12, 물리 6 |
| mainCPU(ns) | main 스레드 CPU 시간 |
| workerCPU(ns) | ForkJoinPool 워커 스레드 CPU 합. 이번 호출 구간의 증가분 |
| 기타 자바 스레드(ns) | main도 워커도 아닌 Java 스레드 CPU 합. 출처는 `getThreadInfo()` |
| 자바 아닌 스레드(ns) | procCPU에서 Java 스레드 CPU 합(main + 워커 + 기타 자바 스레드)을 뺀 나머지. ThreadMXBean이 id를 주지 않아 스레드별로 잴 수 없는 몫이다. GC 작업 스레드, JIT 컴파일러 스레드, VM Thread 등이 들어가고 측정에서 빠진 몫도 섞인다 |
| GC(ms) | GC 수집 시간 증가분. 실제 흐른 시간 기준 근사 |

| 평가 반복문 합(ns) | 말단 작업들의 4중 루프 전체 경과 시간의 합. 여러 말단이 동시에 실행되므로 겹치는 시간이 각각 더해진다 |
| 평가 1회당 워커 CPU(ns) | 재는 값이 아니라 계산값. 표의 workerCPU ÷ 말단 작업(평가 횟수). 프로브가 출력한 값 그대로 |
